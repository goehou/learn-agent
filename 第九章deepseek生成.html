从上下文压缩到文件级持久化：彻底解决 AI Agent 的健忘症

💡 跨会话文件记忆：manifest 唯一权威 + 原子提交 + 锁。
压缩有损且会话结束即失。本章加一层不参与压缩、跨会话保留的存储：Markdown + YAML frontmatter。memory 集合用 manifest 作为唯一权威指针，写入先加锁再 fsync + 原子替换。

1 本章要掌握的目标
  • manifest 是当前记忆集合的唯一权威指针，MEMORY.md 是可重建派生视图。
  • 每条记忆 .md 同时受 200 行 / 4096 UTF-8 bytes 限制。
  • 读改写先经过进程内队列再获取文件锁，避免并发交错。
  • 加载时重新校验 manifest、文件名、realpath 与每条记录。
  • 整理（达到阈值 10 条）在锁内重读、一次提交、失败不丢数据。
2 核心知识点
为什么选文件系统

没有服务负担，每条记忆是 .md 可人读；LLM 生成读取自然；不需要额外数据库；内容可对照 manifest 定位。

一份集合，两份派生视图

.memory/manifest.json 唯一权威；MEMORY.md 由当前集合生成的有界目录；<name>-<id>.md 是单条记忆。读取集合只认 manifest 中列出的文件。

.memory/manifest.json        权威指针
.memory/MEMORY.md           可重建有界目录
.memory/<name>-<id>.md      单条记忆 (frontmatter + body)
加载：先选名称，再读正文

MemorySession.beginTurn(query) 把查询和有界目录交给选择器，模型返回 name 数组（最多 5 条）。选择失败时降级为确定性关键词匹配（英文 3 字符 token，中文 bigram）。

[["user-preference-tabs", "project-database-rule"]]
→ 选中正文包在 <relevant_memories> 中
→ 只进入本次请求，不污染 canonical history
写入：从 canonical history 提取

完整回答后 MemorySession.complete() 调用 extractor，从完整 canonical history 提取跨会话信息。任意一项 schema/类型/slug/大小非法，整批不提交；提取失败只记 lastError。

整理：先声明替换来源，再一次提交

达到阈值（默认 10 条）时，consolidator 返回 source_names + records。未列入 source 的记忆必须保留。提交顺序：锁内重读 manifest → 生成 fsync 新文件 → 原子替换 manifest → 才清理旧文件。

验证基础记录未变
→ 合并未参与/并发新增/本轮记录
→ 生成并 fsync 新文件
→ 原子写入索引
→ 原子替换 manifest
→ 提交成功后才清理被替换旧文件
