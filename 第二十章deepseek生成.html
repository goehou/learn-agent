1 本章要掌握的目标
  • 同一 AgentRunner 与同一组合根 buildAgent(P20, deps)。
  • 每轮一个不可变 Registry Snapshot；一个 tool call 恰好配一个 tool result。
  • Prompt 与 Hook 都不是授权边界；工作区边界、plan gate、McpToolPolicy 都硬性生效。
  • 动态 prompt 增加 runtime_status（mcp_connections / pending_work）。
  • 资源关闭逆序 Mcp → Teammate → Cron → JobSupervisor，单资源失败不跳过其余。

单一循环的真实执行顺序

UserPromptSubmit → drain typed events → 选择 Memory + 压缩 → 渲染 dynamic prompt + Registry Snapshot → RecoveryManager → 追加 assistant → 每个 tool call（校验→Context→Pre→权限→handler/后台→Post→回填）→ 无工具时 Stop 至多一次续跑。

每轮:
  UserPromptSubmit Hook
  → drain typed events
  → Memory + 压缩完整消息组
  → 渲染 dynamic prompt + Registry Snapshot
  → RecoveryManager 调模型
  → 对每个 tool call ...（Pre→权限→handler→Post→配对结果）
  → 无工具调用时 Stop Hook（至多续跑一次）
三个不能破坏的不变量

① 一次回复只用一个 Registry Snapshot；② 一个 tool call 必须恰好配一个 tool result；③ Prompt 和 Hook 都不是授权边界。

4.1 一次回复 = 一个 Registry Snapshot
4.2 一个 tool call = 一个相同 tool_call_id 的 tool result
4.3 Prompt 指导，Policy 授权；Hook 只在硬边界内扩展
runtime_status 动态段落

组合根在每轮渲染前读取可同步状态：mcp_connections 与 pending_work。它只是状态同步 getter，不替代 EventInbox，也不作为授权依据。

关闭和重建也是业务行为

注册顺序 JobSupervisor → Cron → Teammate → MCP；close 逆序 Mcp → Teammate → Cron → Supervisor。重建后 SQLite Task、Memory、Cron pending、Mailbox/Protocol、Worktree binding 各自恢复；已确认事件不重放，未知副作用不盲目重试。

注册:  JobSupervisor → CronRuntime → TeammateRuntime → McpRuntime
关闭:  McpRuntime → TeammateRuntime → CronRuntime → JobSupervisor
单资源失败仍继续尝试剩余；多异常组成 AggregateError
