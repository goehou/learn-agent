从“一锅炖”到“模块化”：重塑 AI Agent 的逻辑骨架

💡 DynamicPromptRenderer 固定顺序渲染：identity → tools → workspace → skills → memory。
一大段硬编码字符串本质是把配置藏在代码里。本章把 System Prompt 拆成固定顺序、运行态取值的五个 section，每个能力有唯一来源，Prompt 只负责渲染。缓存必须属于会话。

1 本章要掌握的目标
  • 固定顺序：identity → tools → workspace → skills → memory。
  • 运行态取值：工具名、workspace、Skill 目录、选中记忆实时读取。
  • Context 必须是严格 JSON，非法值更新缓存前失败。
  • 缓存属于会话实例，键覆盖全部可见输入。
  • P10 关闭记忆系统自己的消息注入，避免同一正文出现两次。
2 核心知识点
固定顺序，运行态取值

renderer 直接读取已参与运行的对象，按固定顺序输出五个 section。即使没有工具，tools section 也明确显示 (none)。

const sections = [
  `## identity\n${identity}\ncontext: ${contextJson}`,
  `## tools\n${toolCatalog}`,
  `## workspace\n${workspace}`,
];
if (skillCatalog.length > 0) sections.push(`## skills\n${skillCatalog}`);
if (memoryBody.length > 0) sections.push(`## memory\n${memoryBody}`);
Context 必须是严格 JSON

只接受 JSON object，值递归限制为 scalar / array / object；拒绝 NaN、无穷、循环引用、symbol key。合法值按键排序、紧凑 JSON 序列化。

type JsonValue = boolean | number | string | null
  | readonly JsonValue[] | JsonObject;
缓存必须属于会话

缓存放在 renderer 实例字段，每次 buildAgent 新建，天然会话隔离。键 = identity + context + tools + workspace + skills + memory。

buildAgent(P10, ...) → 新 DynamicPromptRenderer
cacheKey = identity + context + tools
  + workspace + skills + selected memory
零参数 Provider 接入唯一 Loop

AgentRunner 只依赖一个零参数 provider，每次模型请求前调用 render()。返回空串或非字符串立即抛错，不回退到构建期固定 systemPrompt。

render(): string {
  return this.#renderer.render({
    identity, tools, workspace, context,
    ...(skills ? { skills } : {}),
    ...(memory ? { memory } : {}),
  });
}
记忆只注入一次

P09 由 MemorySession.beforeModel() 追加系统 context 消息；P10 改为 selected memory 进入动态 Prompt 的 memory section，并关闭原消息注入。

new MemorySession({
  ...,
  emitContextMessages: false,  // P10 起关闭独立消息注入
});
createMemorySession(deps, !dynamicPrompt)  // P09 用 true
3 机制流程
1
读取运行态对象

renderer 读取已参与运行的工具/workspace/skill/memory。

2
按固定顺序渲染

identity → tools → workspace → （可选）skills → （可选）memory。

3
生成缓存键

覆盖全部可见输入的规范快照；相等则复用。

4
Provider 每轮调用 render

Loop 在每次模型请求前读取零参数 provider。
